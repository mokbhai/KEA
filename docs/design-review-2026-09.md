# Vox — design-principles review (SOLID / DRY / patterns)

_38 findings confirmed out of 62 raised; 7 area reviewers + 7 adversarial verifiers, 2026-09-19._

## Verdict

This codebase knows what good looks like and applies it inconsistently. The pure-decision extraction in `commands.rs` (`dictation_hotkey_action`, `hold_dictation_action` — unit-testable functions taking a state triple), the RAII guard family (`BusyGuard`, `ProcessingGuard`, `RunGuard`, `PreviewGuard`, `AxRef`), the `RewriteMode` enum with `PromptOverrideRepo` binding `as_str()` at the SQL edge, and the trait-object `EngineRegistry`/`FeatureRegistry` are all genuinely well-chosen abstractions — several of them better than what most desktop apps of this size carry. The problem is that each one stops at the file where it was invented: `AxRef` exists and the function 40 lines below it leaks two CF references by hand; `RewriteMode` exists and `Meeting.status` is a `String`; `CapKind { Llm, Stt, Tts }` exists and `SlotResolver` writes its resolution policy out three times; `BusyGuard` exists and the "finish the action row as error" epilogue is hand-copied 29 times. The result is a repo where the second instance of every pattern is a copy rather than a call, and those copies have already drifted in at least six places — with two confirmed live defects (a CF leak in the dictation hot path, a lost optimistic-rollback in MeetingsPage) and one silently dropped user setting (STT language).

## Cross-cutting themes

**A. Descriptors are built, then never dispatched on.** The repo repeatedly defines exactly the right data — `CapKind` on `CapSlot`, `Command { id, title, default_accelerator }` on `Feature`, `OnnxModelKind`, `new_system_audio_capture()` + `UnavailableSystemAudioCapture` — and then hand-writes the `match` next to it instead of reading it. `Feature::commands()` has zero production consumers while `commands.rs` keeps four hand-written accelerator constants; `OnnxModelKind` is serialized to the UI but never read for dispatch while five `match kind.as_str()` sites disagree on the unknown-kind arm; the SCK factory and null object have no callers at all. Covers [1], [10], [11], [13], [20], [22], [23], [26], [31]. **Fix:** one rule — if a descriptor type exists, dispatch must go through it. Parse the IPC kind string into `ModelKind` once at the command boundary, build `HOTKEY_ACTIONS` from `Feature::commands()` via a `FeatureRegistry::find_command`, and give `SlotResolver` a single `resolve(feature, CapKind)`.

**B. Cleanup and finalization live at the call site instead of in an owner.** The same epilogue — close the ledger row as error, warn on failure, return a string — appears 29 times in `crates/features`; the download lifecycle (key derivation, insert-under-lock, temp-path recording, emit) appears twice in `commands.rs` and *is* the cancellation contract; the optimistic-save/rollback/flash cycle appears in eight UI handlers; `e instanceof Error ? e.message : String(e)` appears 73 times. Every one of these has already drifted somewhere. Covers [8], [9], [19], [27], [32], [34]. **Fix:** one owner per lifecycle — an `ActionGuard` RAII type in `feature.rs`, a `start_download` helper holding the lock/cleanup/emit contract, a `useOptimisticSetting` hook, a `toMessage` export. This is the theme with the highest ratio of deleted lines to added indirection.

**C. Seams hand back raw primitives, so every consumer re-derives the policy.** `HttpClient` returns `(u16, String)` and three engines invent three different 2xx rules — and `EngineError::Auth` consequently never fires for a server 401. `SettingsRepo::get` leaks its `Option<Option<T>>` encoding, so both Option-valued callers carry the same turbofish-and-flatten workaround plus a near-verbatim warning comment. Nine `query_as::<_, (…)>` tuple shapes are positionally hand-mapped into structs that could derive `FromRow`. Lifecycle states and model kinds cross IPC as bare `&str`. Covers [0], [2], [3], [5], [6], [26], [30]. **Fix:** push the encoding behind the seam that owns it — `map_status` in `http.rs`, `SettingsRepo::get_optional`, `#[derive(sqlx::FromRow)]`, enums at the IPC boundary. Each is small; together they remove the entire class.

**D. Tests are pointed at copies of the production path.** `resolve_replace_with_fallback` is a `#[cfg(test)]` restatement of `replace_with_mode_sync` that both fallback tests drive instead of the real dispatcher — in a file whose own comment argues against exactly that ("a test against the private helper would not have caught a caller that forgot to consult it"). `run_tts` is dead in production but carries the tests that make TTS look covered. The `default_accelerator` tests assert `is_some()` rather than binding the crate value to the shell value. Covers [11]/[22], [18], [29]. **Fix:** use the production injection seams that already exist (`set_ax_insert_fn_for_test`, `AxTrustOverride::force`, `FakeSck`) and delete the test-only twins.

## Findings

**1. The finalize-as-error epilogue is hand-copied 29 times, and the meeting path inlines it six more** — `crates/features/src/dictation.rs:131` (+ `meeting.rs:408-630`) · DRY / SRP · **high** · medium
*(merges [8] and [9] — the six double-finalization blocks in `run_meeting_stop` are 12 of the 29 copies and one guard closes both.)* `grep -c 'failed to finish action as error in DB'` gives dictation 10, meeting 6, rewrite 4, tts 3, plus six `'failed to mark meeting as error in DB'` halves. `run_dictation_with_storage` alone closes the ledger by hand at ten early returns. They have already drifted: `dictation.rs:182` writes `"...bind the rewrite llm slot"` to the DB while `dictation.rs:193` returns `"...bind the rewrite llm slot for audio refinement"` to the caller, and the same split repeats at 197/208. `run_meeting_stop` spans 222 lines of which ~145 are six identical `meetings.complete(id,"error",..)` + `actions.finish(action_id,"error",..)` + two `tracing::warn!` blocks, while `ActiveMeeting` (`meeting.rs:231`) holds exactly the `{meeting_id, action_id}` pair each block needs and has zero methods.
**Fix:** `struct ActionGuard<'a> { actions: &'a ActionRepo, id: i64, outcome: Option<..> }` in `crates/features/src/feature.rs` with `async fn fail(self, e: impl Display) -> String` / `async fn succeed(self)`, plus a private `async fn run_inner(..) -> Result<T, String>` per feature so bodies become flat `?`-chains. For meetings, add `impl ActiveMeeting { async fn fail(&self, meetings, actions, e) -> String }` so the guard owns both rows. Do *not* also restructure `run_meeting_stop`'s audio/no-audio split (see Deliberately not flagged).

*(merges [23], [11] and [22] — all three are the same table written in different shapes.)* Five dispatch sites: `compiled_default_accelerator` (`:2187`), the literal 4-tuple array in `check_hotkey_collision` (`:2206`), the `set_hotkey` registration match (`:2334`), the same match again in the `Reassign` arm (`:2394`, carrying the comment `// Unreachable: Reassign only targets known pairs.` — an invariant the array would make structural), and `main.rs:496-519`. **4. Every repo hand-maps anonymous SQL tuples instead of deriving `sqlx::FromRow`** — `crates/core/src/store/meetings.rs:92` · DRY · **high** · medium
`grep -rn FromRow --include="*.rs" .` returns zero hits. `meetings.rs:92-138` (list) and `:142-186` (get) each declare the same 9-wide tuple and hand-map it with a pure identity closure; the same shape repeats at `meetings.rs:188/210`, `conversations.rs:83/120`, `actions.rs:51/78/103` (a 10-column `ActionDetail`), `hotkeys.rs:26/60`, `preset.rs:38/54`, `bindings.rs:17`. Adding one column to `meetings` today means four coordinated edits — tuple type, destructuring pattern, struct literal, twice over. Worse than boilerplate: positional mapping means a `SELECT` whose same-typed columns are reordered (`Meeting.id`/`title`/`started_at` are all `String`) still compiles and silently mis-maps; `FromRow` matches by name.
**Fix:** `#[derive(sqlx::FromRow)]` on `Meeting`, `MeetingSegment`, `MeetingNotes`, `ConversationSummary`, `Message`, `ActionRow`, `ActionDetail`, `HotkeyBindingRow`, `RewritePreset`, `Binding`; replace every `query_as::<_, (..)>(..).map(|(..)| Struct{..})` with `sqlx::query_as::<_, Meeting>(..)`. ~200 lines deleted, no API change.

**5. The two download commands duplicate the cancellation contract, and `ModelDownloader` duplicates its install spine** — `src-tauri/src/commands.rs:2556` and `:3095` · DRY · medium · medium
*(merges [27] and [19].)* `download_whisper_model` (`:2555-2605`) and `download_onnx_model` (`:3095-3155`) repeat ~45 lines verbatim: `download_key` → `ModelStorage::new` → `temp_file_for` → lock `active_downloads` + `contains_key` early return → the same "handle is registered while the lock is held" comment → `spawn` running `run_download_task`, `guard.remove(cleanup_key)`, the `Ok`/`Err` emit match, `guard.insert(ActiveDownload { model_id, temp_path, task })`. **6. The `HttpClient` port returns a raw status and demands a bearer token, so `EngineError::Auth` is unreachable for real 401s and keyless local LLMs cannot work** — `crates/engines/src/http.rs:12` · DIP / ISP · medium · medium
*(merges [5] and [6] — same port, same file, one signature change fixes both.)* All three methods return `(u16, _)`, and each caller invents its own rule: `llm/mod.rs:22` uses `!(200..300)`, `stt/openai.rs:68` uses `status != 200` (a 202 from a compatible transcription endpoint becomes an error), `tts/openai.rs:62` adds its own `from_utf8_lossy` preview. `grep EngineError::Auth` finds only the four keychain lookups and one test assertion — so the variant whose message is "authentication failed: … check the API key in provider settings" can *never* fire for a server 401, the most common wrong-key case, which instead surfaces as `HTTP 401: {body}`. Separately, `bearer: &str` is baked into every signature, so `llm/compatible.rs:40` hard-fails with `Auth("missing api key")` while `ProviderRow.tsx:58` renders "No key needed" for `local-llm`, `capabilityDefaults.ts:158-166` marks it `ready: isLocal` with no credential, and `ConnectStep.tsx:114-121` auto-binds it. A user who completes local-server onboarding and rewrites text is told to fix an API key the app said they did not need; every `compatible.rs` test hides this by seeding `FakeCredentials::with_key("local-llm", ..)`.
**Fix:** change the port to `async fn post_json(..) -> Result<String, EngineError>` with one private `fn map_status(status, body)` in `http.rs` mapping 401/403 → `Auth`, 429/5xx → retryable, other non-2xx → `http`; and replace `bearer: &str` with `Auth::{None, Bearer(&str)}` applied in one place in `ReqwestHttpClient`. Skip the three-role-trait split — there is exactly one non-production implementer and its two `unreachable!()` stubs cost ~12 lines.
